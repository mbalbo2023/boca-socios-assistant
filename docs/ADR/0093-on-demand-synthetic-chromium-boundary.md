# ADR 0093: Bounded on-demand synthetic browser boundary for BETA

**Status:** code-only candidate for [#227](https://github.com/mbalbo2023/boca-socios-assistant/issues/227), 2026-11-01 ART. Based on `main=4b1d219c2ba1739dc20c9c103170beedff8c1607`. No new browser service, container, host setting, SSH port, production traffic or live reservation has been installed or exercised.

## Context and the narrow code decision

The existing BETA already has `BetaCoordinator` (ADR0057), a durable one-ticket guard, a single on-demand async command drain, stop/recovery (ADR0068), and a served command host (ADR0069). `SyntheticTicketScenario` and `SyntheticBrowserPort` (ADR0011) already define a fixed, fake DOM flow with no Boca/Queue-it URL or account argument. The controller's current `_LocalSyntheticBrowser` responds with a deterministic fake result, **not** a Chromium observation. The optional `scripts/run_synthetic_ticket_flow.py` is an isolated Playwright laboratory smoke, **not** part of that runtime.

This change adds `boca_socios.browser.on_demand.OnDemandSyntheticBrowser` as a disposable `SyntheticBrowserPort` implementation. An injected zero-argument async `PageFactory` provides a fresh `PagePort` context; construction launches nothing. A call performs only the existing `SyntheticTicketScenario` and accepts only `RESERVED_IN_SIMULATOR`. One active call at most; a concurrent call refuses `worker_busy` without creating another page. A finite cooperative cancellation deadline (default 15 seconds, maximum 30) bounds ordinary fake journeys; cancellation/normal completion exits the page context. **Python cancellation is not a hard process deadline** when third-party code suppresses it. `close()` fences new work, cancels an active task and joins for at most five seconds; an uncooperative page raises `worker_teardown_unverified`, requiring **the isolated host runner to kill that disposable process**. A late result after close, external STOP, or expired deadline is refused *after the page factory's context exit*, even if that exit swallowed `CancelledError`. The adapter cannot choose a URL, receive credentials, make a purchase or claim external confirmation.

`build_beta_server(settings, *, browser=None)` gains an explicit synthetic port injection seam, reusing `LocalBetaRuntime.start(browser=...)`; its default remains `_LocalSyntheticBrowser`. There is **no automatic startup, browser import, IPC, shell command, fallback to live mode or second deployment entrypoint**. No additional scheduler or queue is introduced: the existing coordinator remains the single owner of idempotent member/event work, local notices and recovery. The adapter itself does **not** provide exactly-once semantics; that belongs to the persistent command/guard ledger.

The optional `browser.playwright_factory.isolated_playwright_page()` supplies a concrete async `PageFactory` inside the **separate isolated worker**. It lazy-imports the browser-only pinned Playwright package, launches headless Chromium with background networking disabled, starts one fresh nonpersistent context (`service_workers=block`, downloads disabled), aborts **every** page URL request (`**/*`), yields its initially blank page for the embedded synthetic HTML, and closes context/browser in nested `finally` scopes. Example *inside an already verified network-none worker*: `OnDemandSyntheticBrowser(isolated_playwright_page)`; no controller or host code invokes this by default. Its Playwright route cannot constrain Chromium background sockets; the Docker network policy is mandatory. This is a code-capable factory, **not** evidence that a container or runtime IPC is wired.

## Boundaries and limits that deployment must prove

The adapter's `validate_worker_boundary` refuses unless the executing process is effective UID and GID **10002** and its visible cgroup v2 has finite `memory.max` no greater than **768 MiB**, `pids.max` no greater than **128**, and `cpu.max` no greater than **one CPU**. A Docker cgroup namespace must be private; otherwise a parent/aggregate cgroup reading may not prove the worker's own budget. Missing, unreadable, `max` or oversized limits refuse before opening a page. The test-injected boundary callback is for trusted unit fixtures only; an actual worker must use the default check. These are the existing ADR0021/Dockerfile.browser ceilings, not capacity claims about the droplet.

Checking cgroup/UID cannot prove network isolation. A real disposable browser process additionally requires a **Docker-enforced `network_mode: none`/`--network none`**, nonroot user, read-only filesystem, bounded `/dev/shm`, no added privileges, no Docker socket, no broad host bind, no owner/key/data volume, no secret mount/environment and no host port. Playwright route interception or `about:blank` are additional defenses, **not** replacements for the OS no-egress boundary. If any boundary, page cleanup or exact image identity cannot be proven, stop/fail closed and selectively remove only the positively identified disposable Boca worker. Do not prune or touch another application.

The synthetic DOM models no provider session. `RESERVED_IN_SIMULATOR`, command `COMPLETED` and a local notification remain internal fixture facts; actual Boca inventory, Queue-it position, admission, payment, ticket ownership, external confirmation and passkey readiness are **not observed**. The worker must never load Boca, Queue-it or another external page in this phase.

## Proposed IPC/host architecture — **not implemented or approved**

Exactly one architecture decision remains before changing Compose, any host helper, or a protected Actions command:

1. **Recommended for separate owner review:** a Boca-scoped, non-egress sidecar under UID10002 with an idle control loop and a fixed **Unix-domain socket** on a new, narrowly permissioned disposable IPC mount. Chromium itself starts only when the coordinator sends the one fixed synthetic command and is torn down after one journey. The controller receives a structured synthetic-only result or failure; it never mounts Docker socket, accesses browser state, shares secrets or opens a TCP port. Design a bounded authenticated/local-peer, size-capped protocol; enforce a single-flight gate and container kill on deadline/failed teardown. The sidecar image digest, mount provenance and resource limits need explicit host review. Even an idle sidecar has memory/lifecycle cost; measure it.
2. Alternative: a trusted Boca-only host launcher creates a fresh `--network none` Chromium container per command and pipes one fixed request/result. This would need an explicit privilege boundary outside the unprivileged BETA controller, protected host installation/cleanup code and an exact image contract. It is **not** acceptable to mount `/var/run/docker.sock` into the controller or grant it Docker daemon privileges.
3. Rejected: launching Chromium inside the controller's UID10001 container, accepting arbitrary page URLs, opening HTTP/TCP sidecar ports, enabling egress, or treating CI's smoke as live booking. These weaken the separation or exceed authorization.

The `PageFactory` and explicit runtime injection are the reusable code seams for a later IPC adapter, **not evidence that either IPC option exists now**. Before activation, request owner approval for the concrete separate host/Compose scope, port/socket mount, image digest and cleanup behavior; use the sole manual protected GitHub Actions workflow, exact-main checks and positive Boca-only inventory. Issue #225's Chrome passkey activation, `127.0.0.1:8443` SSH tunnel and immediate selective Docker failure cleanup are separate gates and must not be displaced by this worker.

## Verification and Rule 84

New synthetic tests exercise zero startup, one DOM path, blocked concurrent calls, budget refusal before page creation, timeouts, page cancellation, bounded teardown with an uncooperative fixture, no late success (including swallowed cancellation during `__aexit__` for close, STOP and timeout), coordinator stop, one member/event/quantity1, durable restart/recovery, no repeated page, local notice and explicit served-runtime dependency injection. A monkeypatched Playwright API verifies lazy launch, all-route abort, synthetic DOM transitions, refusal before import and closing on success, tampered UI and page-open failure. They use temporary SQLite and fake pages. Full lint/mypy/policy and exact candidate CI must still be reported on the final pushed SHA; none of these tests proves actual Chromium, Docker no-egress, OS cgroup enforcement or droplet resource headroom.

The module owner updates this ADR/contract; the central documentation owner reconciles README, delivery plan, integration status, #45 and #25 before any closure. The first real-BETA browser host activation remains **NO-GO pending architecture approval, implementation, immutable artifact/CI evidence, positive isolated inventory and controlled acceptance**.
