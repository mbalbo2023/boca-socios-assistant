# ADR 0222 — Captura del arranque en el Cutover de Boca

## Evidencia y alcance

El worker del [Cutover #893](https://github.com/mbalbo2023/boca-socios-assistant/actions/runs/42658939650) terminó con código 1 en menos de cinco segundos, con OOM falso y sin resultados de healthcheck. [#895](https://github.com/mbalbo2023/boca-socios-assistant/actions/runs/42664858124) verificó el controlador anterior en loopback 8443 y cero workers. El manifiesto de la release contiene ambos archivos del propietario y permite su lectura por UID 10002. La ausencia en la imagen queda descartada. Faltó información del proceso para identificar la causa interna. Los cinco dictámenes, la inspección OCI y los controles reproducibles se conservaron en [#417](https://github.com/mbalbo2023/boca-socios-assistant/issues/417#issuecomment-6754980250).

La [PR #457](https://github.com/mbalbo2023/boca-socios-assistant/pull/457) verificó en Docker real que un lector adquirido antes de arrancar observa salidas inmediatas. R132 integra ese lector en el adaptador externo. El titular aprobó el coste operativo del driver `none`: `docker logs` carecerá de la salida ordinaria de este worker durante su vida. La configuración del controlador sigue su propio contrato. La investigación se limita a Docker Boca y a ejecución en simulación.

## Orden y custodia

1. La Action protegida autentica el intento, el propietario, la release dual y el SHA actual de main. El mismo proceso conserva el lease para comprobar el socket rootless, crear el contenedor y verificar CID, imagen, intento, montajes y logging. El healthcheck del worker conserva su exit status y redirige sus dos canales. Docker puede generar mensajes de sistema propios sobre un fallo al ejecutar ese healthcheck.
2. Con el contenedor detenido, el lector verifica que el Engine admite la versión de API y que el attach no-TTY al CID completo respondió HTTP 101. Inicia la lectura antes del único start. La falta de confirmación impide arrancar y activa la compensación selectiva. El límite del flujo es 64 KiB, 512 marcos y ocho segundos. El lector se desconecta sin enviar señales al proceso.
3. Ante una salida confirmada, se registra la categoría en un archivo de modo 0600 del directorio privado de recibos Boca. El registro queda ligado al intent, SHA, imagen y CID antes de retirar el contenedor. Se sincroniza el archivo y el directorio. El terminal V5 incorpora la observación cuando la evidencia V4 y el registro previo concuerdan. Las formas históricas V1–V4 siguen disponibles.
4. El runner verifica el intento y el SHA antes de mostrar una categoría en el job. Si falla la fase del host, una lectura independiente y acotada del registro usa la misma invocación y la misma release. Si el job pierde conectividad o se cancela, la publicación del resumen puede faltar. El marcador permite la lectura posterior cuando llegó a persistirse. Una categoría producida a partir de stderr identifica una salida observable y necesita corroboración antes de atribuirla a un componente.
5. Tras arrancar el candidato, una conexión AF_UNIX sin carga útil desde su UID verifica las credenciales que el kernel asigna al listener del worker. Se vuelve a comprobar el worker y el puerto local del controlador antes de la aceptación. El socket puede recibir el cierre de esa conexión. No se envía una orden de simulación, reserva o navegación. La aceptación de Chrome, sesión del titular y Telegram requiere sus propios recibos.

El ZIP reproducible completo contiene 43 entradas, 922733 bytes de fuentes y 229475 bytes comprimidos, con SHA-256 `a903cfefe6e18dd70c28c4c1190730a219169489464bbf10a64d79d81f642070`. El preflight contiene 7 entradas, 489661 bytes de fuentes y 106444 comprimidos. La recuperación contiene 7 entradas y 44922 bytes comprimidos. Los límites de transporte siguen siendo 512000 bytes para Cutover y 128000 para cada variante reducida.

La validación física se publica en [#417](https://github.com/mbalbo2023/boca-socios-assistant/issues/417) y [#45](https://github.com/mbalbo2023/boca-socios-assistant/issues/45). El control de estado conserva el fallo original y exige evidencia de limpieza por identidad exacta.
