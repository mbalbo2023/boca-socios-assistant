# ADR 0013: Read-only accessible simulation snapshot

Status: Proposed for review, 2026-10-28. Partial issue #16.

## Decision

The panel is a pure renderer for a caller-supplied, bounded in-memory snapshot.
It has no route, listener, DB connection, credential import or runtime wiring.
`PanelEntry` accepts only opaque bounded IDs, a typed simulation status, an
aware timestamp and quantity exactly one. Duplicate member/event pairs are
rejected. Member and event identifiers are used only to group and sort data;
HTML receives per-page numeric pseudonyms and no identifiers.

The generated page has visible Spanish button names usable by voice control,
52-pixel minimum targets, keyboard focus outlines, touch-sized controls,
semantic headings and list items, a live region for filter results, a responsive
layout, and Buenos Aires timestamps. Filtering is local JavaScript over the
snapshot. The page has no fetch, remote script, form submission or secret field.
All apparent admissions and reservations are explicitly labelled fictitious.

## Consequences and gate

The snapshot is never a source of truth for ticket confirmation. It does not
implement the durable outbox, Telegram delivery, owner authentication, secure
credential enrollment, a deployed service or live Boca integration. A future
adapter must read durable status data after #20/#22 integration, redact it,
authenticate the owner, protect the route with TLS and session/CSRF controls,
and decide a privacy-safe durable label scheme. That integration requires its
own review and tests before any endpoint is exposed. No HTML generated by this
module is enabled in the default Compose runtime.

Automated tests cover semantic controls, redaction, timezone conversion,
duplicate/quantity guards and bounded data. Manual Android/iOS voice and
screen-reader testing remains necessary once the owner-only route exists.
