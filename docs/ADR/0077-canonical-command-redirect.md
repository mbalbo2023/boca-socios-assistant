# ADR 0077: canonical command redirects after durable deduplication

**Status:** integrated by PR #187 in
`b92e2abacd63d1654dfb6d795f718af2ea283589`. Exact candidate
`6c0ade927811f19f331c68b2b6b3e7a0bf8b8ed9` passed CI 41274391525,

## Failure and decision

The private panel used the UUID generated by a new form for its redirect after
`BetaCommandHost.begin()`. The durable coordinator can instead return an
existing command for the same member/event. After a new session or restart,
the new UUID is an alias for that existing intent, but it has no detail row at
`/comandos/{new}`. A 303 to that URL produced 404 while the original command
remained valid. The initial test-only commit in PR #187 reproduced the mismatch
before changing the handler.

The handler now accepts only a canonical nonzero UUID from the returned command
snapshot. It records that ID in the session operation result and redirects to
`/comandos/{canonical}`. Repeating the same POST uses the stored redirect
without invoking the host again. A missing/malformed returned ID produces the
existing generic uncertain-result 503 and no Location header; the caller must
inspect the command history before trying a different action. The host's
durable member/event uniqueness and quantity-one constraints remain the
authority. No new key, state transition, reservation or Boca interaction is
introduced by the redirect fix.

## Evidence and limits

`test_new_command_key_redirects_to_existing_canonical_result` seeds one
durable command and has the host return it for a new form UUID. It checks the
first/repeated redirect, one host call, valid old detail and missing new detail.
`test_malformed_command_result_never_becomes_a_redirect` checks fail-closed
handling. The exact final SHA, Actions runs and technical review belong in PR
#187 once completed. These are synthetic WSGI/SQLite tests; they do not prove
TLS, a real owner passkey, Site, Telegram or a deployed service.

Root cause, prevention and executed selectors are retained as RCA-186 in
`docs/quality/rca-lessons.json`. Root owns central status and #45 under Rule
84 after integration; this ADR cannot turn a code fix into host acceptance.
