# G17 #1241 — forensic terminal observation (CODE_ONLY)

**Authority:** issue #417, comment 6980866434, plus unanimous 4/4 Option D amendment. **Base:** `main@7f20bf0acf43b2e17812bfc35efc86a552b5a404`. **Author:** independent, local feature worktree; Root owns GitHub, review and any eventual Action.

## Question and evidence boundary

`boca-pair-upgrade-apply` #1241 / run `44315372494` timed out before its terminal receipt. Later read-only runs #1242–#1244 observe a healthy installed G17 controller and a created worker; they **cannot** certify that historical transaction's terminal result. G16 `75b00d8e1cd903d3d727a2628134a27fd740fc42` was the pre-upgrade source; G17 `7f20bf0acf43b2e17812bfc35efc86a552b5a404` and release `44313076076` are fixed historical coordinates. This code must not repeat APPLY, touch state or infer ACCEPTED from health.

## Design — approved Option D

1. One new protected workflow dispatch selector `boca-pair-upgrade-incident-observe-1241`, main-only and explicitly owner-triggered, with existing Boca SSH identity and fixed resource budget. Preflight rejects injected coordinates, restart/retry, stale main or unrelated inputs. No second deployment selector or release.
2. Host-side SHA-pinned, isolated memfd ZIP runs **only** Python stdlib + the existing inert `host_cutover_stage` open/read helpers and the new forensic reader; neither production pair actor nor CLI is in the host ZIP. The reader accepts no path, CID or source argument; only the current observation run ID for framing. It checks dedicated UID/GID 10001, real Boca directory `0700`, exactly the five attempt-scoped candidate filenames `.boca-pair-upgrade-44315372494.{evidence,intent,commit,technical-postflight-v2,terminal}`, files `0600`/nlink1, `openat O_NOFOLLOW`, bounded bytes, stable `stat`/inode/read-back and a second independent snapshot. It **never** creates/locks/removes/renames anything; no Docker, service, SQLite, HTTP or network operations.
3. It validates canonical, duplicate-free JSON for evidence/intent/technical witness, binds SHA(evidence) → intent and SHA(intent) → commit, old/source/release/attempt, witness identity and technical installed pair/binding, and preserves absence or corruption as finite NO_GO/UNKNOWN categories. The *technical* filename is `technical-postflight-v2`, never a guessed legacy `.postflight`.
4. Host stdout is **solely a private bounded binary frame**, not a public log. Its authenticated SSH pipe is redirected to an exclusive runner-local `0600` tempfile under `umask 077`, with no `tee`, command substitution, artifact upload, `set -x`, or echo of bytes. The frame carries a canonical redacted metadata summary (hashes, finite classifications, identities solely as a private correlation payload) and the **unchanged ≤1024-byte terminal receipt**. On error, emit a fixed redacted failure frame, not a terminal surrogate. The runner checks frame length, checksum, required fields, mutually consistent result and no trailing bytes.
5. Only the runner, from its full source checkout, invokes the existing canonical `host_boca_pair_upgrade_cli.verify_upgrade(terminal, "44315372494")`. It correlates terminal CIDs to the double-read intent/technical evidence and, where independently verifiable, prior read-only receipts #1242–#1244. Never add an alternate terminal parser or change the CLI. Runner outputs only enum/reason/marker-presence and digests, `observer_writes=0`, `recovery_authorized=false`, `beta_deploy=NO_GO`. Tempfile removal is ensured in a trap even on timeout/signals.
6. Only terminal `ACCEPTED` plus matching commit and valid technical evidence can be classified `HISTORICAL_TERMINAL_ACCEPTED` (technical only). A canonical `NO_GO` is reported as `HISTORICAL_TERMINAL_NO_GO`; incompleteness, races, ambiguity or absent terminal remain `UNKNOWN`, never SUCCESS. The historical GitHub Actions run stays timed-out/FAILED even if the durable terminal later proves accepted.

## Explicit exclusions / acceptance

No changes to UI, motors, Telegram, owner login/passkey, booking, worker, lease, storage, existing APPLY or Porota. No host execution until independent review, tests, exact-sha CI and four new GO_FINAL votes. Tests require legitimate ACCEPTED and NO_GO fixtures; absent/partial/corrupt/symlink/hardlink/mode/truncation/race/double-read/frame tamper/oversized and publication-leak negatives, tiny bundle SHA and operation-only workflow guard, 120s timeout/no retry. Stop if a field lacks a grounded canonical mapping; don't guess its meaning.
